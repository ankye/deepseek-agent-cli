# Benchmark Runtime Hardcode Removal Design

## Boundary Model

Shared runtime packages must be benchmark-agnostic. They may schedule staged work, project tools, apply workflow boundary guards, record evidence, and close terminal states, but they must not branch on benchmark names, task ids, instance ids, scorer terms, or benchmark-specific profile ids.

共享 runtime packages 必须 benchmark-agnostic。它们可以调度 staged work、投影工具、应用 workflow boundary guards、记录 evidence、关闭 terminal states，但不得基于 benchmark names、task ids、instance ids、scorer terms 或 benchmark-specific profile ids 分支。

The host evaluation adapter owns benchmark facts. It may prepare datasets, create isolated checkouts, invoke harnesses, collect predictions, classify diagnostics, and render benchmark reports. Those facts must cross into runtime only as ordinary task data, tool results, workflow events, or externally supplied profile data.

host evaluation adapter 拥有 benchmark facts。它可以准备 datasets、创建隔离 checkouts、调用 harnesses、收集 predictions、分类 diagnostics 并渲染 benchmark reports。这些事实只能以普通 task data、tool results、workflow events 或外部提供的 profile data 形式进入 runtime。

## Dynamic Profile Rule

The phase-1 profile is not source code. A benchmark-like task profile may be generated by the model, loaded from an external profile artifact, or supplied by a host controller as declarative data. CLI/runtime responsibilities are limited to:

第一期 profile 不是源码。benchmark-like task profile 可以由模型生成、从外部 profile artifact 加载，或由 host controller 以声明式数据提供。CLI/runtime 的职责仅限于：

- parse and validate the profile payload;
- 解析并校验 profile payload；
- reject unknown executors, cycles, undeclared refs, budget overages, or unsafe tool exposure;
- 拒绝 unknown executors、cycles、undeclared refs、budget overages 或 unsafe tool exposure；
- compile to the generic staged workflow contract;
- 编译到通用 staged workflow contract；
- schedule through generic workflow controls and record replayable evidence.
- 通过通用 workflow controls 调度并记录可回放 evidence。

The CLI must not contain a hardcoded phase-1 profile that dictates benchmark-specific stage order, expected patch behavior, or scorer-specific close conditions.

CLI 不得包含硬编码第一期 profile 来规定 benchmark-specific stage order、expected patch behavior 或 scorer-specific close conditions。

## Generic Scheduling Replacement

Existing benchmark gates map to generic workflow primitives:

现有 benchmark gates 映射为通用 workflow primitives：

- "route to benchmark runner" becomes an externally declared stage with `allowedTools` and `progressCapabilityIds`.
- “route to benchmark runner” 变成外部声明 stage 的 `allowedTools` 与 `progressCapabilityIds`。
- "source inspection budget" becomes generic stage acceptance and terminal close policy, not a runtime string gate.
- “source inspection budget” 变成通用 stage acceptance 与 terminal close policy，而不是 runtime string gate。
- "post edit verification" becomes a verification stage with allowed test capabilities and evidence requirements.
- “post edit verification” 变成带有 test capabilities 与 evidence requirements 的 verification stage。
- "ready for harness" becomes a host adapter decision after consuming runtime evidence, not a runtime benchmark terminal branch.
- “ready for harness” 变成 host adapter 消费 runtime evidence 后做出的决定，而不是 runtime benchmark terminal branch。

## Enforcement

Architecture lint SHALL reject benchmark-specific tokens in shared runtime and shared platform packages. The initial forbidden token set includes `SWE_BENCH`, `SweBench`, `sweBench`, `swe-bench`, `swebench`, `SWE-bench`, and known benchmark instance-id patterns such as `owner__repo-123`.

Architecture lint 必须拒绝 shared runtime 与 shared platform packages 中的 benchmark-specific tokens。初始 forbidden token set 包含 `SWE_BENCH`、`SweBench`、`sweBench`、`swe-bench`、`swebench`、`SWE-bench`，以及类似 `owner__repo-123` 的已知 benchmark instance-id patterns。

The allowlist is narrow:

allowlist 必须保持狭窄：

- `src/apps/cli/src/diagnostics/swe-bench-*`
- `src/apps/cli/src/host/swe-bench-run-capabilities.ts`
- host adapter tests for those files
- OpenSpec change documents that discuss this removal

`src/packages/runtime`, `src/packages/platform-contracts`, `src/packages/prompt-assembly`, `src/packages/core-coding-tools`, and task-profile catalog source are not allowlisted for benchmark-specific behavior.

`src/packages/runtime`、`src/packages/platform-contracts`、`src/packages/prompt-assembly`、`src/packages/core-coding-tools` 与 task-profile catalog source 不在 benchmark-specific behavior 的 allowlist 中。

## Migration

1. Add failing lint/contract coverage that reports existing benchmark hardcode.
2. 增加失败的 lint/contract 覆盖，用于暴露现有 benchmark hardcode。
3. Remove runtime SWE-bench gate state and prompt/profile classifiers.
4. 移除 runtime SWE-bench gate state 与 prompt/profile classifiers。
5. Preserve generic workflow orchestration tests and strengthen them where removed behavior was actually generic.
6. 保留通用 workflow orchestration 测试，并在被删除行为本质上是通用行为时加强这些测试。
7. Move host-only benchmark diagnostics to adapter code without changing runtime scheduling.
8. 将 host-only benchmark diagnostics 移到 adapter code，不改变 runtime scheduling。
9. Validate OpenSpec, focused lint/tests, typecheck, architecture boundaries, and only then run a single task-1 canary to measure first-pass scheduling behavior.
10. 先验证 OpenSpec、focused lint/tests、typecheck、architecture boundaries，再运行单个第 1 题 canary 来度量 first-pass scheduling behavior。
