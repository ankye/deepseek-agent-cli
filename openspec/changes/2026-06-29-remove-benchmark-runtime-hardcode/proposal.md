# Remove Benchmark Runtime Hardcode

## Why

The current SWE-bench supervision path encoded benchmark-specific routing gates, request budgets, and profile behavior inside shared runtime code. That is a forbidden cheating mechanism: it optimizes for a scoring harness shape instead of proving general CLI scheduling and workflow orchestration ability. It also failed the simplest target evidence: SWE-bench Lite task 1 still stalled after many benchmark-specific iterations, so the hardcode did not solve the real scheduling problem.

当前 SWE-bench 监督路径把 benchmark-specific routing gates、request budgets 与 profile behavior 写进了共享 runtime 代码。这属于被禁止的作弊机制：它优化的是评分 harness 形态，而不是证明 CLI 具备通用调度和 workflow orchestration 能力。并且它连最基础的证据目标也没有达成：SWE-bench Lite 第 1 题在多轮 benchmark-specific 迭代后仍然卡住，因此这些 hardcode 没有解决真实调度问题。

The first-phase profile must also not be hardcoded into CLI or runtime source. Profiles for benchmark-like work must be generated by the model or supplied as external/declarative profile data, then admitted through the same generic compiler and governance path as any other dynamic profile.

第一期 profile 也不得硬编码到 CLI 或 runtime 源码中。benchmark-like 工作的 profile 必须由模型生成，或作为外部/声明式 profile 数据提供，然后通过与其他 dynamic profile 相同的通用 compiler 与 governance 路径准入。

## What Changes

- Remove benchmark-specific state machines, gates, request budgets, prompt classifiers, and static profile selections from shared runtime packages.
- 清理共享 runtime packages 中的 benchmark-specific state machines、gates、request budgets、prompt classifiers 与 static profile selections。
- Keep benchmark dataset, harness, prediction, and diagnostics code only in host-owned evaluation adapter surfaces.
- 仅在 host-owned evaluation adapter surfaces 中保留 benchmark dataset、harness、prediction 与 diagnostics 代码。
- Add architecture lint and contract coverage that fails when benchmark tokens or known benchmark instance identifiers appear in runtime/shared packages.
- 增加 architecture lint 与 contract 覆盖：当 benchmark tokens 或已知 benchmark instance identifiers 出现在 runtime/shared packages 中时直接失败。
- Require dynamic or externally supplied task profiles for benchmark-like workflows; CLI/runtime may load, validate, compile, and schedule profiles, but must not embed the phase-1 benchmark profile as source-code behavior.
- 要求 benchmark-like workflows 使用 dynamic 或外部提供的 task profiles；CLI/runtime 可以加载、校验、编译和调度 profile，但不得把第一期 benchmark profile 作为源码行为内置。
- Express scheduling through generic staged workflow controls: ready-stage control, allowed tool projection, progress capability ids, workflow boundary guards, evidence-driven stage advancement, stage acceptance mode, and terminal close policy.
- 通过通用 staged workflow controls 表达调度：ready-stage control、allowed tool projection、progress capability ids、workflow boundary guards、evidence-driven stage advancement、stage acceptance mode 与 terminal close policy。

## Non-Goals

- Do not manually solve any SWE-bench task.
- 不手工解决任何 SWE-bench 题目。
- Do not encode expected patches, repo names, instance ids, task numbers, upstream commits, or known scorer behavior.
- 不编码 expected patches、repo names、instance ids、task numbers、upstream commits 或 known scorer behavior。
- Do not lower budgets or add budget reminders as a substitute for real scheduling correctness.
- 不用降低预算或增加预算提醒替代真实调度正确性。
- Do not remove the host-owned SWE-bench diagnostics/evaluation adapter itself when it is clearly isolated from shared runtime behavior.
- 不移除清晰隔离在 host-owned 层的 SWE-bench diagnostics/evaluation adapter 本身。
